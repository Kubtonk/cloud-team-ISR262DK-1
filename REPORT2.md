### 2. Назначение проекта

### 3. Перечень использованных элементов Markdown
В обновленном файле `README.md` применены следующие элементы разметки:
* **Заголовки:** `#`, `##`
* **Цитаты (Blockquotes):** `>` (в описании и примечании о безопасности)
* **Таблицы:** 3 таблицы (архитектура, структура репозитория, краткая справка по моделям IaaS/PaaS/SaaS)
* **Списки:** маркированные (`-`) и нумерованные (`1.`)
* **Кодовые блоки:** с синтаксисом `bash` (команды Git) и `text` (схема процессов и структура)
* **Ссылки:** на файлы проекта (`docs/*.md`), профили участников и документацию GitHub
* **Выделение текста:** полужирный (`**text**`), моноширинный (``code``)

### 4. Описание архитектурных компонентов
* **README.md:** Главная точка входа, описывающая правила, структуру и архитектуру.
* **docs/models-comparison.md:** Таблица сравнения моделей IaaS, PaaS, SaaS.
* **docs/services-examples.md:** Каталог практических примеров сервисов.
* **GitHub Workflow:** Платформа управления задачами (Issues), ветками, Pull Request и Code Review.

### 7. Ответы на контрольные вопросы

**1. Для чего файл README.md используется в GitHub-репозитории?**  
Файл `README.md` служит визитной карточкой и главной технической документацией проекта. Он автоматически отображается на главной странице репозитория и объясняет назначение проекта, его архитектуру, структуру и порядок работы.

**2. Какие элементы Markdown позволяют структурировать техническую документацию?**  
Заголовки (`#`-`######`) задают иерархию, таблицы структурируют данные, кодовые блоки (```) выделяют команды и схемы, а списки и цитаты улучшают читаемость.

**3. Какие сведения необходимо включить в инструкцию по запуску облачного проекта?**  
Системные требования, команды клонирования репозитория (`git clone`), шаги по настройке окружения, команды сборки/запуска и методы проверки работы системы.

**4. Почему реальные пароли, токены и ключи доступа нельзя размещать в README.md и других файлах репозитория?**  
Публикация секретов приводит к компрометации системы: боты-сканеры и злоумышленники могут моментально перехватить ключи и получить доступ к облачным ресурсам. Секреты должны храниться в переменных окружения.

**5. Каким образом качественная документация упрощает командную разработку и сопровождение облачной системы?**  
Она снижает время онбординга новых разработчиков, фиксирует архитектурные стандарты, снижает число ошибок и делает развертывание воспроизводимым.
